## 人工核对发现的问题与修复

1. **缓存阻止补齐**：旧代码把同 feed hash 的原文摘录也视为分析完成。
   现在只复用正文哈希、原始标题、模型与 prompt 版本均一致的成功摘要。
2. **新摘要无法替换旧摘要**：数据库和增量合并按长度保留内容。
   现在批量入库把正文、摘要、证据与哈希作为同一代结果更新；正式入库效果待恢复数据库后验证。
3. **版本间串文**：RocksDB 11.1.2 的正文曾混入 11.1.1 的 PinnableSlice
   破坏性接口变更。通用正文提取器删除了版本标题，单纯提示词无法可靠补救。
   现在保留 GitHub release body 的标题，再按带日期的版本标题截断历史记录。
   本次结果仅保留关闭只读实例可能删除并发读写实例活跃 SST 文件的修复。
4. **导航与广告污染**：PostgreSQL 新闻页的 PostgreSQL 19 Beta 横幅、GitHub
   的 Repository navigation 和 “commits since this release” 曾被当成事实。
   现在提取已知正文容器；没有 release body 时不使用导航内容。
   最终 52 条摘要中上述污染字符串为 0。
5. **版本号误判及过度合并**：113.2 billion 行被识别为版本号，正文提及相同版本
   的不同文章也可能合并。现在只从发布标题提取版本，近似标题必须有一致的标题版本。
6. **引用不稳定**：模型逐字复述仍会改写标点或合并原文。现在模型选择 `S1` 等
   段落 ID，服务端附原文；未知 ID 被拒绝。引用完整性有自动检查，语义仍需人工判断。
7. **营销指标缺少条件**：性能数字必须以“作者报告/厂商测试称”归因，保留负载、
   基线、价格模型及未覆盖条件。ClickHouse 对比摘要现在标明列表价建模、
   部分费用排除和对手未纳入的功能；DuckDB Agent Mode 摘要同时指出
   CLI 输出 token 减少没有转化为整体成本或时间收益。
8. **页面掩盖故障**：数据库失败时返回快照但不提示。现在 API 标记存储来源与降级，
   页面明确告知；GitHub Atom 的日期标记为“源更新”，避免当成首次发布日期。

## 质量评价与剩余边界

目前足以作为日常数据库研究的筛选入口：主体信息具体、引用可追溯、
性能结论有归因，重复刷新也能补齐而非重复付费。正文充分的 33 条已完成本轮分析。

仍不能视为自动事实核验系统：精确引用不证明所有概括均被引用支持；厂商测试没有
独立复现；输入最多 14,000 字符，超长文章可能丢失后部条件；未知网站布局仍可能
带入样板文字。19 条正文不足的发布信息需要更丰富的上游 release notes，
当前明确保留缺口。近似标题去重采取保守策略，跨渠道同一事件仍可能有多条。

```bash
cd liminalis
.venv/bin/python -m scripts.radar_quality --refresh --rounds 2
```
