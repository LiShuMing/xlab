# 工程研读日报目录规则

生成、修订、汇总 `docs/daily/` 时，读取本文件和
[engineering-daily skill](../skills/engineering-daily/SKILL.md)。详细状态语义见
[README](README.md)。本目录是文档工作流，没有网站构建清单。

- 日报采用「一条连续学习主线＋少量真实变化＋一道新题＋一道到期回忆」。
  课程、题目、参考解分别保存，日报以阅读导航串联。
- 内容深度来自明确契约、机制、反例、源码/测试证据与可执行验证思路。
  字数与来源数量不作为质量证明。
- 写作前运行 `history`、`plan`，读取上次相关课程和报道。稳定身份、状态变化、
  知识增量与练习能力分别去重；解释为什么本次值得重访。
- 新闻须实时核实官方来源，记录事件时间、核查截止时间与阶段。不可达不能推断无更新。
  GitHub 合并、提案采纳、实现落地、版本发布分别核实。
- 源码证据固定到 commit，至少定位文件和符号。ISA 文档只证明语义；
  代码生成分析、作者 benchmark 与本机实测分开。没有对应硬件不写实测结果。
- 题目先给约束、边界用例与交付要求。用户作答或明确索要答案后，才创建
  `practice/answers/` 中对应文件；不要在题目、日报、HTML 折叠区提前嵌入解答。
- 发行清单仅代表已生成。读取/实践/掌握需要真实反馈；未作答保持待练。
  原始反馈与运行证据放 `.local/engineering-daily/`，不要提交。
- 同日期更新同一日报与清单，不改历史事实来消除重复。纠错保留旧结论的来源及修订理由。
- 交付前运行 `check` 并检查本次新文档的相对链接。
  历史日报可被链接，但不能把历史 PR 状态写为今天已核实。
