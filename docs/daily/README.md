# 工程研读日报

日报承担一个职责：把新变化、连续课程与真实练习串成当天可完成的阅读路径。
当前主线是 Highway「可移植数组过滤与聚合」。JDK、Linux 与语言动态提供
少量相关材料；主线结束或复盘决定切换之前，不每天另开一套课程。

## 规范、项目、skill 如何分工

| 载体 | 作用 | 入口 |
| --- | --- | --- |
| 文档项目 | 保存课程、题目、公开证据与发行记录；可以直接在 Obsidian/GitHub 阅读 | 本目录 |
| 目录规范 | 所有生成入口都遵守的质量、去重与证据规则 | [AGENTS.md](AGENTS.md) |

先用 Markdown、JSON 与 Python 标准库形成闭环。已有 Panming/Radar 可以将来提供候选
素材，但本流程不依赖它们在线，也不另建抓取后台。skill 保存在仓库中，通过根目录
路由发现；在聊天中可以说「按 docs/skills/engineering-daily/SKILL.md 生成今天日报」。
它尚未安装成用户全局 `$engineering-daily` 命令。

## 每天的阅读预算

| 模块 | 内容 | 建议预算 |
| --- | --- | --- |
| 今天必读 | 主结论、与上一课的增量、一个核心边界 | 忙时 5 分钟 |
| 今日变化 | 通常精选 3–5 条，可为 0；每条说明变化、阶段、影响、阅读决策 | 3–5 分钟 |
| 连续学习 | 一个知识单元，机制、具体输入、反例、源码/测试、验证任务 | 15–20 分钟 |
| 每日练习 | 一道题，约束、边界输入与交付要求；不附解答 | 15–25 分钟 |
| 旧知识回忆 | 到期知识的一个提取问题，不提前给提示 | 2 分钟 |

日报正文建议约 1,000–1,800 中文字，课程约 1,500–3,000 字，属于预算而非验收指标。
没有足够证据时缩短。不能为了填满字数复制背景、指令表或多个独立长文。
课程的篇幅用于解释机制与边界；日报只摘要、说明联系并链接完整材料。

## 怎样做到「更充实」

课程至少交付一个能迁移的判断：例如「把结果掩掉，不等于没有进行越界读取」。
围绕它展开：真实工程场景 → 明确输入/输出契约 → 数据或状态如何移动 →
能推翻错误理解的反例 → 固定版本源码/测试 → 最小验证与仍然未知的部分。
比较实现时解释相同语义怎样落地、支持哪些类型/目标、代价来自哪里。
不要求每日覆盖所有 ISA，不用 API 数量代替理解深度。

## 内容为什么不会每天重复

1. **事件身份**：GitHub 使用 `github:owner/repo:pr:N`，JEP 使用 `jep:N`，
   WG21 使用 `wg21:Pxxxx`；URL 镜像、newsletter 转述归并到同一身份。
2. **事件增量**：记录 `stage` 与 `delta_key`。同身份、同阶段、同技术增量不再发布；
   「多了提交/评论」不足以构成增量。状态变化、修复机制变化、新反例/测试、发布或回移
   可以重访，但必须链接上次报道，说明旧结论如何修订。论文/博客重读属于学习，不冒充新闻。
3. **知识身份**：课程固定 `unit_id`，并记录本课新增边界。改标题、换数据库例子或换 ISA
   不自动成为新课。跨课若讲同一问题，必须说明从哪一层推进到哪一层。
4. **练习身份**：用 `skill_key` 表示所考察的推理能力。14 天内相同能力的新题默认拦截，
   仅允许标明旧题来源的复习/补救，或说明更高要求的变式。代码题换变量名不能避开这一规则。
5. **窗口之外**：工具的窗口只是机械检查；写作前还要读相关历史摘要，做语义判断。
   到期复习与新闻纠错有意重复，必须说明重复的原因。

公开去重账在 `editions/YYYY-MM-DD.json`。历史 GitHub/邮件汇总中的 PR/JEP/提案链接
会参与查重；它们只证明以前报道过，不能证明当前状态。
同日重跑覆盖同一文件和发行记录，并保留仍有效的分析、纠错记录与首次出现的链接。

## 连续性与学习状态

`editions/` 记录**已生成**的材料，不能据此声称已送达、已读或已掌握。
用户反馈与练习证据保存在 Git 忽略的 `.local/engineering-daily/` 中。
「已读」需用户确认；「已实践」需实际作答或运行证据；「已掌握」还需正确性评价、
边界解释与后续复习证据。脚本只能检查证据字段与复习顺序，不能判断答案是否真的正确。

未作答标为待练，不按失败或正确处理。主线积压达到两课时，下一期默认补救/复习其中一课，
不继续推进新单元。课程编号是学习顺序，不是日历日期；14 个单元可以用更长时间完成。
每课未解决的问题保留在课程末尾；用户反馈之后才能把它改为已解决。

复习使用最近一次有效作答日期为锚点的第 1/3/7/14 天，不是相邻间隔累加。
答错或部分理解则重新从反馈日期起算；提前答对不会消耗未来的到期复习。
未按时作答保留原到期日期，下一次提示为逾期，不伪造已完成。
周复盘只统计真实反馈，若一周没有反馈就明确说明没有可评估的掌握证据。

## 本地源码与版本证据

[sources.json](sources.json) 定义四个阅读源：Highway、SIMDe、OpenJDK JDK、Linux。
`SIMD` 不是单一仓库，这里选择 SIMDe 作为跨 ISA intrinsic 语义参考，同时保留
已有 `cc/simd/` 实验入口。仓库已声明的 `cc/thirdparty/simde` 子模块未初始化；
本流程使用独立阅读镜像，不改子模块锁定的版本。

源码位于 `.local/engineering-daily/sources/`，采用 shallow、partial 与 sparse clone。
首期按文件取tag/API、intrinsic、对象发布/GC、调度/内存入口，避免初次就下载整个测试树。
热点范围在配置中列出；未取到的目录不表示上游没有该实现，按课程补充`sparse`路径，
再运行`sources init --repo ID`应用配置；目录或单文件都可以。
每日可更新干净的镜像，保存前后 SHA；阅读证据始终链接固定 SHA 的文件/函数/测试。
工作区有修改时不自动更新；引用该SHA前核对`snapshot`的`worktree_clean`，
不要把本地改过的文件当作原始commit的内容。
master 是开发快照，不能当作已经发布的 JDK 或 Linux 版本。
浅克隆的提交日志不能当作完整历史；需要跨版本分析时针对性 deepen 或获取所需 tag。
`changed_files`只描述当前选定范围的源码差异，不是上游全仓变更清单；新闻仍需官方来源核查。

```bash
# 根目录运行；Python 3.9+，不需要安装依赖
python3 tools/engineering_daily.py sources snapshot
python3 tools/engineering_daily.py sources update --repo highway
# HTTPS传输持续失败且本机已有GitHub SSH认证时，按命令切换，不改全局Git配置
python3 tools/engineering_daily.py sources init --transport ssh
python3 tools/engineering_daily.py history --date 2026-10-14
python3 tools/engineering_daily.py plan --date 2026-10-14
python3 tools/engineering_daily.py check docs/daily/editions/2026-10-13.json

# evidence 指向真实反馈/作答文件；个人内容放 .local/ 下
python3 tools/engineering_daily.py feedback --id highway-01 --level read \
  --date 2026-10-14 --evidence .local/engineering-daily/read-confirmation.md
```

`sources init` 可以恢复未克隆的阅读镜像；`sources update` 才会联网更新源码。
计划、查重、校验都是只读；同日报告生成完成之后才写入公开发行记录。
发行字段参考[清单模板](templates/edition.json)。同一份反馈账的更新按顺序执行，
不要让多个任务并发写入本地进度文件。
私人反馈不会自动导出到日报，也不提交运行缓存、源码镜像或原始聊天。

## 现有简报怎样接入

候选输入统一来自已有 GitHub 日报、公开技术汇总和官方来源。先按规范身份合并，
再按正确性/并发/内存/性能/兼容性影响选少量条目，深度分析留在专题文档并链接。
一条信息即使同时出现在 GitHub、官方博客和 release notes 中，也只占一个日报位置。
发布状态可以引用 release notes 补充，不能从 PR 合并推导为已发布。

本次已建立统一阅读入口与历史查重；现有自动通知没有被停用或重新配置。
接入已有日报任务时，把生成指令改为使用本 skill、写入 `docs/daily/`，
并在验收通过后只发送核心摘要与该日报链接。独立 P0 通知可保留，普通摘要归并。
可复制的任务指令见 [生成任务指令](generation-prompt.md)，调度时刻由原任务决定。

## 验收

- 新课解释上一课尚未解释的一个机制/边界，并链接确实存在的源码或权威资料。
- 新闻有身份、阶段、日期、证据与最小验证思路；来源不可达标为未核实，不写「无变化」。
- 每日只有一道新练习，题目文件不含参考解；到期回忆不默认等于已复习。
- 发行清单通过 `check`；仍要人工评估语义重复、证据是否支持结论、练习难度与阅读预算。
- 每周输出真实作答、错误模式、逾期复习、未解决问题与下一周的主线调整。
