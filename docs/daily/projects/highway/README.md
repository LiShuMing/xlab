# Highway：可移植数组过滤与聚合

主线产物：一个有标量参考结果、明确边界与可比较代码生成的数组处理小项目。
阶段A做整数变换/条件聚合，阶段B做浮点点积，阶段C做稳定过滤输出，最后才讨论分派与性能。
14 个学习单元是两周建议，不要求连续14个日历日完成。

| 单元 | 核心问题 | 本次增量与验收 |
| --- | --- | --- |
| 01 | lane、宽度与标量契约 | 定义输入域、输出、空输入与溢出边界；区分元素数/字节数 |
| 02 | load/store 与地址 | 对齐/非对齐、指针步进、别名；整数变换与标量结果比较 |
| 03 | 算术与循环骨架 | 不同lane数的全块循环；为什么不能写死一台机器的宽度 |
| 04 | 比较与mask | 区分比较结果、选择与内存访问；建立条件聚合 |
| 05 | 尾部与安全读取 | `0/1/N-1/N/N+1`，标量尾部或具有相应保证的受限读取 |
| 06 | 扩宽、窄化与饱和 | lane类型、lane数量、符号和溢出的不同契约 |
| 07 | 归约与复习 | 空输入、负数、极值；证明向量累加器何时可能先溢出 |

## 平台比较方式

每天固定一个语义，再选择必要平台：Highway的抽象/API约束、x86 AVX2/AVX-512、
Arm NEON/SVE；遇到向量长度与mask语义时加入RISC-V V。
SIMDe只作为intrinsic实现参照，不当作Highway的内部实现或所有ISA的性能oracle。
同一API可能展开为多条指令；指令语义相同也不能推导Intel/AMD的吞吐相同。

主资料：[Highway quick reference](https://github.com/google/highway/blob/master/g3doc/quick_reference.md)、
[Arm ACLE](https://arm-software.github.io/acle/main/acle.html)。每课补充固定版本实现及测试。
未有对应硬件时仅做源码与代码生成分析；交叉编译成功不等于运行正确或性能已测。

## 首期契约与未解决问题

- 阶段A输入为`int32_t`，`n <= 1,000,000`，阈值也为`int32_t`，聚合结果为`int64_t`。
  这个输入上限使总和绝对值不超过约`2.15e15`，标量oracle在该范围不会溢出。
  输入元素的变换仍需单独约束，不能从总和安全推导每个lane运算安全。
- 阶段C保持输入的相对顺序，输出容量至少`n`；先约定输入输出不重叠，后续如需原地过滤
  必须另证读取/写入顺序，不能悄悄修改契约。
- 阶段B采用单独的浮点误差与NaN/Inf契约，不复用整数逐值相等准则。
- 当前未解决：不同目标的安全尾部实现、窄lane归约的溢出、compress写入范围、
  分派目标选择与本机可复现benchmark。尚未完成实测，也没有用户掌握证据。
