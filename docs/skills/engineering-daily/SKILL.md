# 工程研读日报

在 xlab 根目录工作。读取 `docs/daily/AGENTS.md` 与 `docs/daily/README.md`；
用 `tools/engineering_daily.py` 查询发行历史、学习积压和到期复习。
详细栏目与字段参考 `docs/daily/templates/`，源码范围参考 `docs/daily/sources.json`。

## 生成或修订日报

1. 按 Asia/Shanghai 确定报告日期、核查截止时间；读同日文件、`history --date`、
   `plan --date`、当前主线的路线图与上一课。首次接入也查询历史 GitHub/邮件技术汇总。
2. 已有本地源码时保存 `sources snapshot`；需要新的源码变化时对相关镜像执行
   `sources update --repo ID`。从固定 SHA 读文件/符号/测试；浅历史不足则明确缺口。
3. 搜集少量官方动态，按规范身份合并。对已报道事件核实阶段或技术增量，写清
   旧结论与新证据的差异。JEP/发布、WG21/工作草案/编译器/标准库分开记。
   没有重要变化可以零条；来源不可达则写覆盖不足。
4. 按 `plan` 建议选一个知识单元。积压时默认补救或复习，只有用户要求仍推进
   或反馈证明不积压时才选择新课。解释一个机制，给具体输入、反例、证据及验证任务。
   SIMD 每天围绕一个语义选必要 ISA 对比，不照抄整张 API/指令清单。
5. 发一道 15–25 分钟练习。默认周一 C++、周二 JVM、周三 Linux、周四系统设计、
   周五算法、周六排障、周日复习；主线或错题需要时可调整并记录理由。
   用 `skill_key` 查同能力近期题，变式要说明难度/约束增量。再附一道到期回忆；
   首期没有旧单元时用基础自测，不能编造此前学过的知识。
6. 按模板写日报和 `editions/YYYY-MM-DD.json`，链接课程和题目，运行 `check`。
   机械检查之后人工审查语义重复、引用支持程度、正确性边界与阅读预算。
   最后在聊天中给核心摘要、一道题的摘要与本地阅读链接。

同日重跑保留有效的深入分析和实验记录，修订事实并说明新增内容；不重新计为新课。
参考解在用户作答/明确索要之后生成，不能提前写入日报或题目。

## 用户反馈与批改

先读取该题与用户实际答案。依次给必要的分级提示、反馈、参考解、正确性论证、
复杂度、边界测试与工程取舍。分级提示以 H1 反例、H2 不变量、H3 实现线索推进；
用户希望继续尝试时停在合适级别，完整答案存独立 `practice/answers/`。

原始作答保存到 Git 忽略的本地证据文件，再用 `feedback` 记录课程/题目 ID、
日期、`read/practiced/mastered` 及 `wrong/partial/correct`。不要把模型生成的答案
当作用户证据；运行通过只证明相应测试，不能独立证明用户已掌握。
掌握还需真实作答、边界解释与后续复习。错题按反馈日期重新安排 1/3/7/14 天复习。
将公开、匿名的错误模式和未解决问题补入课程；私人内容留本地。

## 周复盘

用 `plan` 和本地状态查看本周真实反馈，读本周发行清单与课程问题。
按 `templates/weekly.md` 总结实际练习、误解、到期/逾期复习、没有证据的部分与下周安排。
没有作答则明确「无可评估的掌握证据」，优先安排低负担回忆和旧题。
不因为累计发送了七期就切换学习主题。
