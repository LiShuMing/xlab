## 一、算法笔试与现场编码

### 1. 最小化批次峰值（核心）

**题目**：N 个文件具有正整数字节数，按既定顺序分成至多 M 个非空连续批次，使最大批次字节数最小。

**追问**：如何构造单调判定并二分答案？说明边界、整数溢出和复杂度。

**参考要点**：对候选容量 B，贪心地按顺序装满当前批次，再检查所需批次数是否
不超过 M。可行性随 B 单调；二分范围为最大单文件大小到总大小。时间
O(N log S)，S 为总字节数；使用足够宽的整数并安全计算中点。

### 2. 外存精确去重

**题目**：大量 64 位 ID 无法全部装入内存，要求输出不重复 ID，无须排序。

**追问**：怎样分区、落盘并控制打开文件数量？分区仍过大或哈希分布不均时怎么办？

**参考要点**：按哈希分区写入外存，每个分区在内存中去重；同一 ID 必须进入同一
分区。内存不足时可继续分区或采用外排序。限制缓冲与文件句柄。分区字节数大不
一定意味着唯一值多，应避免机械地反复切分。

## 二、计算机语言

### 3. `unordered_map` 句柄失效（核心）

**题目**：代码缓存了迭代器，随后插入大量元素。另一个模块保存了元素地址。
两者是否仍可使用？

**追问**：rehash、erase 分别影响什么？多线程查询与插入能否因此认为安全？

**参考要点**：rehash 会使迭代器失效，但通常不使已有元素的指针和引用失效；
删除对应元素后，相关句柄失效。地址稳定不提供并发同步：查询与修改同一容器仍
需满足线程安全要求。不要把 `vector` 的规则直接套过来。

### 4. Python 异步异常传播

**题目**：多个请求通过 `asyncio.gather` 并发执行，一个请求抛异常，其余请求
是否停止？

**追问**：与 `TaskGroup` 有何区别？主调用超时后，远端操作是否已经终止？
按 Python 3.11+ 讨论。

**参考要点**：默认 `gather` 可向等待者传播首个异常，而其他任务不会因此自动
全部取消。`TaskGroup` 对普通子任务异常会取消其余任务并等待收尾。取消等待也
不保证外部副作用撤销。参考
[Python 3.12 任务文档](https://docs.python.org/3.12/library/asyncio-task.html)。

## 三、操作系统与性能工程

### 5. 批次越大，吞吐越高但体验越差（核心）

**题目**：批处理大小增大后，吞吐提高，p99、内存峰值和超时数也上升。

**追问**：如何拆解组批等待、执行和排队时间？多级流水线怎样放大在途内存？

**参考要点**：分开测量组批、排队、执行和回传。更大批次可能提高摊销效率，
同时增加等待和长尾。内存要计算各阶段排队、执行、预取及重试中的数据；单级
队列有界不等于总资源有界。按请求长度或对象大小分组比较。

### 6. epoll 边沿触发卡住

**题目**：非阻塞连接使用 ET，每次事件只读固定数量字节，再调用 `epoll_wait`，
偶尔仍有数据却不再推进。

**追问**：原因是什么？怎样同时保证读完整性和多个连接之间的公平性？

**参考要点**：通常需非阻塞读取到 `EAGAIN`，不能假定每次未读完的数据都会再次
触发通知。若设置处理预算，应由应用保存仍需推进的连接并重新调度，不能只依赖
下一次边沿。读取字节也不等于获得完整业务消息。参考
[epoll 手册](https://man7.org/linux/man-pages/man7/epoll.7.html)。

## 四、项目经验与负责人判断

### 7. 增量数据的统计信息（核心）

**题目**：历史表统计较准确，但新增数据集中在少数键，优化器估算与实际执行
差异明显。

**追问**：全量统计为什么可能无法描述增量？优先观测哪些误差，如何权衡采集
成本与收益？

**参考要点**：历史均值可能掩盖增量的键倾斜、选择性和匹配放大。比较计划估算
与节点实际行数、字节、键分布及资源消耗，再判断补充统计、修正规则或运行时
应对。你真实使用的统计与机制仍待补充，不能直接假设内部实现。

### 8. 物化视图部分刷新失败

**题目**：查询覆盖多个分区，其中部分视图分区已刷新，部分仍旧。能否组合视图
与基表回答？

**追问**：如何证明覆盖完整、无重复且快照语义一致？聚合或多表 Join 会增加
什么约束？

**参考要点**：需明确每个片段覆盖的数据范围与版本，并保证组合无遗漏、无重复。
聚合可能需要正确的状态合并；多表 Join 还涉及其他输入的可见版本。不能仅凭
"这个分区刷新成功"判断可用。无法证明时应拒绝该改写或按契约回退。

## 五、分布式系统与 AI 基础设施

### 9. 训练数据全局去重的增量维护（核心）

**题目**：新增样本与历史样本重复，去重规则要求保留质量最高的代表。怎样避免
每次全量重算？

**追问**：新样本替换旧代表后，哪些旧产物受影响？近似去重与精确去重的正确性
边界有何不同？

**参考要点**：维护重复关系或候选组与代表身份，使新增数据能够定位受影响范围。
代表替换可能使旧数据集成员及下游产物失效，不能只追加新结果。精确规则与近似
候选召回的保证不同，需要分别评估误漏、质量和维护成本。

### 10. Agent 恢复时版本已变化

**题目**：任务保存了检查点，恢复时工具接口、代码仓库和执行镜像均有更新。
还能继续执行吗？

**追问**：检查点需要绑定哪些版本？如何区分可复用结果、需要重验的状态和必须
重新执行的步骤？

**参考要点**：检查点除业务进度外，还需记录输入、代码、工具、环境及产物身份。
按兼容规则判断复用，不能只恢复对话摘要。恢复前确认外部副作用及当前仓库状态；
参数可解析不等于语义兼容。保留旧环境或重新执行也各有成本。
