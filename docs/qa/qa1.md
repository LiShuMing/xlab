**练后核对：参考要点**

**A1：流式中位数**

用大顶堆存较小的一半、小顶堆存较大的一半，保证 `max(小半) ≤ min(大半)`，
且两堆大小差不超过一。插入 O(log N)，查询 O(1)，空间 O(N)。偶数个时取两堆顶平均，
注意整数相加溢出，先转宽类型再算。

内存真正受限时双堆不可行，必须在三种前提里选一种：值域受限走计数数组或位图；
可外存则分层存储；只要近似值则用 t-digest 一类分位数摘要，并给出误差上界。最容易
被扣分的是默认“流式 = 全量精确”。

**A2：节点分配**

按开始时间排序，用最小堆维护各节点最近任务的结束时间。堆顶结束时间不晚于当前
开始时间就复用该节点（弹出后压入新结束时间），否则新建节点。O(N log N)；要输出
方案则堆中存 `(end, node_id)`。

最优性靠下界：任一时刻重叠任务数为 k，就至少需要 k 个节点，贪心恰好达到该下界。
边界必须写死：区间取半开 `[s, e)` 时 `end == start` 不算冲突，取闭区间则算，
两种约定下答案不同。

**A3：`string_view` 生命周期**

`string_view` 只是指针加长度，不拥有存储。返回指向局部对象的视图，函数返回即悬空；
交给异步任务，借用期限跨不过异步边界，回调执行时原对象可能早已销毁；底层字符串
扩容会换地址，修改内容则让观察结果变化并引入并发同步问题。字符串字面量具有静态
存储期，是唯一天然安全的来源。

修复方向有三条：返回拥有式 `std::string`；异步边界改传拥有式数据或显式持有 owner
（如共享缓冲加引用计数）；确实要借用就把生命周期约定写进接口，由调用方保证存活。
用 ASAN（AddressSanitizer）与调试容器兜底，但未释放的内存被读往往不会立刻崩溃，
测试通过不等于正确。

**A4：析构错误**

析构默认 `noexcept`，抛出异常会直接终止进程，栈展开期间更是立刻 terminate。因此
需要业务确认的失败必须走显式接口（`close()` 或 `commit()` 返回错误码或
`std::error_code`），析构只做约定范围内、可预期成功的清理，失败时记录日志并把对象
置为错误状态。

移动后把句柄置空（`nullptr` 或 `-1`），清理函数写成幂等，避免重复释放。还要分清：
析构没报错不等于提交成功，回滚也可能失败；这两件事要么显式完成，要么明确接受
“尽力而为”的语义，不能靠析构兜底。

**A5：`fork` 与 COW**

`fork` 后父子共享物理页，页表项被置为只读；任一方写入触发 COW（Copy-On-Write）
缺页，复制整页并转为私有，于是私有脏页和 minor fault（轻微缺页异常）同时上升。
父子各自的 RSS（Resident Set Size）都把共享页算成自己的，相加会重复计数，应看
`/proc/<pid>/smaps` 的 Private_Dirty 与 Shared_Clean，或用 PSS（Proportional Set
Size）按共享比例摊分。

操作系统 COW 的粒度是页乃至 THP（Transparent Huge Page），触发条件是写，回收路径
是进程退出；Column COW 的粒度是列 chunk 或不可变文件，靠引用计数与版本替换，读路径
完全不变，两者不能类比。另外 minor fault 还有栈增长、大页拆分、page cache 等其他
来源，只凭计数归因容易误判。

**A6：删除但未释放**

`unlink` 只移除目录项，inode 与数据块要等最后一个引用关闭才释放。常见持有者：进程
仍打开该文件、存在 `mmap` 映射、硬链接、容器或挂载命名空间里路径不同。定位用
`lsof +L1`、`lsof | grep deleted`、`/proc/*/fd` 的符号链接，或 `fuser`。

除已删除文件外，`df` 与 `du` 的差异还可能来自统计口径：`df` 统计整个文件系统
（含未被挂载覆盖的目录、保留块），`du` 只统计可见路径；此外还有快照、回收站、日志
轮转残留。处置应是让持有进程优雅关闭或重新打开日志（很多服务响应 `SIGUSR1`），
而不是反复 `rm`。

**A7：规划开销**

分四段打点：候选枚举（视图数乘表匹配）、语义匹配（SPJG
（Select-Project-Join-GroupBy）等价性检查涉及规范化与包含判定）、补偿计算（聚合与
Join 补偿）、成本估算与计划生成。画出“候选数—规划耗时”曲线，判断是线性增长还是
组合爆炸。

控制手段按性价比排序：先用元数据索引（按基表、谓词、分组键建倒排）把候选集砍掉
一个数量级；再用快速必要条件剪枝（表集合包含、谓词蕴含、分组键可除性）；匹配结果
可缓存；最后才是搜索预算（时间或候选数上限）。预算耗尽必须仍给出可执行的基表计划，
保证最坏情况是“没改写”，不是“没计划”。评价不能只看命中率，要同时看规划时延 P99
与端到端时延。

**A8：TTL 与增量维护**

TTL（Time To Live）的两种解释必须区分：作为物化产物保留策略时，删分区只影响
“加速能力”，不影响数据正确性；作为业务可见范围契约时，删分区等于声明该范围不再
被查询。

迟到更新到来后，可选的处置是重算受影响分区、跳过并标记 stale、拒绝写入，或让查询
回退基表，但每一种都要显式写进规则，最危险的是静默漏数据。查询侧因此要能判断
“该范围是否被视图完整覆盖”，覆盖不全就回退基表。跨分区更新要追踪旧、新分区的
双向影响；重建与再次清理要协调版本，避免刚重建就被清掉，或清理与重算并发导致部分
分区来自不同快照。

**A9：推理公平性**

请求数是极差的成本代理，一条长上下文请求可能抵上千条短请求。配额应按 token、算力
或显存占用计，并用“预留加结算”：准入时按输入长度加输出长度估计值预留额度，请求
结束后按实际用量结算，估计偏差从后续配额扣回。

调度用分层配额配 WFQ（Weighted Fair Queueing）一类的加权公平队列，轮转依据是
已消耗成本而非已服务请求数。饥饿保护靠最长等待上限加 aging（等待越久权重越高）。
短请求的尾延迟靠隔离：短、长请求分池或分批次通道，长请求不挤进短请求的 batch。
评价指标应为租户成本份额偏差、TTFT（Time To First Token）与 TPOT（Time Per
Output Token）分位数，以及 goodput（有效吞吐，只计满足时延目标的请求）。

**A10：Embedding 迁移**

不能直接写入。不同模型、预处理、归一化方式产出的向量位于不同空间，混在同一索引里
做相似度检索没有意义，检索结果会既不准又难解释。做法是把模型、预处理、归一化的
版本与索引绑定：索引元数据记录版本，查询必须用匹配版本的 query encoder，版本之间
用影子索引隔离。

迁移路径是双写（旧索引继续服务、新写入同时进新索引）→ 历史数据按批回填 → 按流量
或租户灰度切读 → 保留旧索引至观察期结束以便回退。删除与更新必须在两套索引上都
生效，否则会返回已删数据。质量验证不能只看接口返回 200：用固定查询集比较 recall@k、
NDCG（Normalized Discounted Cumulative Gain）、新旧结果 diff，抽样长尾查询做人工
评估，同时记录延迟与索引体积。
