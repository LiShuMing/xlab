# 盘铭交互与视觉设计

## 1. 设计方向

盘铭采用“每日知识工作台”的体验。打开时先看今天，深入时进入主题、写作与图书馆；以具体内容和下一步操作组织界面。

2026-10-07 查看 [Raft 公开首页](https://raft.build/) 后观察到：奶油白底、黄色导航、粉色主要按钮、粗黑边界、硬偏移阴影、粗体标题，以及少量像素装饰。公开页面中的 Chat / Tasks / Files 分组也展示了将多类对象放在同一工作区的思路。这是公开首页观察，不代表登录后产品全部页面的规范。

盘铭转译为“外层鲜明、内层安静”：品牌导航与主操作保留色块及清晰边界，长文阅读区使用细分隔线和留白。以下 token 为盘铭自定义初稿，不是 Raft 实测色值。

## 2. 信息架构

```text
盘铭
├── 今日                 素材流、日报入口、待处理、一个下一步
├── 素材                 所有 Layer0，原件、解析、知识卡与来源
├── 每日 Report          日历/列表、版本、覆盖率、主题归纳
├── 主题                 关注问题、跨日素材、相关博客与知识
├── 写作台               选题池、系列、大纲、文章编辑、导出
├── 图书馆               书架、书、章节、概念、复习
├── 关注来源             作者、Feed、Repo、更新与健康状态
└── 设置                 偏好、模型处理范围、预算、日程、备份
```

全局搜索覆盖所有层，结果明确显示类型与时间。任务执行日志放在右上角“处理状态”，通常只显示“正在整理 3 项”；操作失败时出现可定位提示。

主路由契约：`/today?date=YYYY-MM-DD`、`/materials/:id`、`/reports/:date?revision=N`、`/topics/:id`、`/studio/:blogId`、`/library/books/:id`、`/library/entries/:id`、`/sources`、`/settings`。

## 3. 布局与视觉系统

### 3.1 桌面布局

- 1440px 参考视口：侧栏 216px，内容区弹性；详情页证据栏 320–380px，可折叠。
- 顶部工作区栏 56px；内容容器左右留白 28px；列表密度支持标准/紧凑。
- 正文最大宽度 720–800px，中文建议每行 35–45 字；宽屏增加证据栏，不拉宽段落。
- ≤1024px 侧栏折叠，证据变为抽屉；≤640px 单栏，今日内容优先，写作结构编辑收进菜单。
- 界面不要求每次切换层级都换页；素材、知识卡和引用可在当前上下文打开。

### 3.2 Token 初稿

| Token | 值 | 使用 |
| --- | --- | --- |
| `canvas` | `#FFF9ED` | 品牌/工作台底色 |
| `surface` | `#FFFFFF` | 正文、列表、编辑区 |
| `ink` | `#20201C` | 主文本、主边框 |
| `muted` | `#62625B` | 时间、说明、辅助元数据 |
| `brand-yellow` | `#F7D85C` | 顶栏、今天/Report 重点 |
| `action-pink` | `#F294B2` | 主要操作与采纳 |
| `info-cyan` | `#B9E5EF` | 来源、证据与信息 |
| `topic-lavender` | `#D8CBF2` | 主题关联 |
| `success` | `#246343` | 已完成/已采纳的文字 |
| `warning` | `#7A4D00` | 部分完成/待验证文字 |
| `error` | `#A12633` | 失败文字 |
| `border-soft` | `#D8D5CA` | 长文分区、非主操作 |

间距用 4 / 8 / 12 / 16 / 24 / 32 / 48px。品牌块 2px 黑边 + `3px 3px 0` 硬阴影，正文卡片 1px 细边且无阴影。圆角 4–8px，避免所有元素变成大胶囊。

标题用系统无衬线粗体；正文用系统中文字体，16–17px / 1.75 行高；代码用系统等宽字体，14px / 1.6。主标题 32px，章节标题 24px，列表项标题 16px。日期、版本、键盘快捷键用等宽小字。

Layer0–3 的色彩标签只帮助导航，所有标签同时显示文字。彩色卡片中的正文使用深色 ink；任何候选色须在实现时验证 WCAG AA 对比度。动效限 120–180ms，支持 `prefers-reduced-motion`。

### 3.3 品牌表达

中文主标“盘铭”，英文小标“PANMING”。图形方向是四层叠页/刻痕：表示每日输入留下结构。像素元素只用于空状态或少量品牌装饰。不要把全部知识关系画成漂浮节点；用户通常需要目录和文章。

## 4. 今日页

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 盘铭 PANMING        搜索素材、问题与知识…         处理状态   ＋收集素材 │
├──────────────┬─────────────────────────────────────────────────────────┤
│ 今日         │ 2026 年 10 月 7 日 · 周三             < 前日  今日 >    │
│ 素材         │ 日日新：今天的输入，下一步的理解                        │
│ 每日 Report  │                                                         │
│ 主题         │ [今日 Report · v1 · 截止 21:30] [6 项待整理]            │
│ 写作台       │ [打开 Report]  [更新 Report：2 项未纳入]                │
│ 图书馆       │                                                         │
│ 关注来源     │ 今日素材                           筛选：来源 / 主题     │
│              │ 时间  标题             来源          状态       操作    │
│ 数据库       │ 10:15 外存 Join 笔记   本机文件       已归纳     阅读    │
│ AI           │ 12:05 研究对话         AI 导出        私有       处理    │
│ 方法         │ 18:20 新版本说明       GitHub         待阅读     阅读    │
│              │                                                         │
│ 设置         │ 可继续写：一个选题            今日复习：两个概念         │
└──────────────┴─────────────────────────────────────────────────────────┘
```

示意中的数字、标题与时间均为演示。真正未连接来源时不显示成功采集数字。

今日默认展示“今天收到”，用户切换“今天发生 / 前日补录”时给出定义。主操作始终“收集素材”；Report 在没有输入时提示“保存第一份素材”，不显示一个大而空的摘要框。

新增素材不会让阅读区域跳回顶部。日期切换写入 URL，可以复制链接。列表排序默认接收时间降序，用户可改成重要性；人工置顶有明显标记。

## 5. 收集与素材详情

### 5.1 快速收集面板

三个模式：粘贴链接/文本、上传文件、导入对话。第一步只有输入与保存按钮；主题、备注、隐私和模型处理选项放在可展开区。

- 链接先保存，再异步读取；页面显示“链接已保存，正在读取正文”。
- Markdown/TXT 保存原件，检测编码并生成规范化文本。
- 粘贴笔记可以直接存为用户内容，保留采集原因。
- 视频链接如果无字幕，显示“已归档链接，待字幕/转录”；不把网页说明写成看过视频。
- 重复内容提示“已有素材，已追加一次收集记录”，提供已有素材入口。
- 单文件默认上限 50MiB，视频原件首版默认只保存链接/用户提供字幕；格式上限由设置和服务端共同执行。

保存按钮收到归档成功或本机 spool 成功后才反馈；关闭弹窗前未保存内容仍保留草稿。拖拽多文件显示逐项成功/失败，成功项不因一个文件失败而回滚。

### 5.2 详情布局

左侧阅读原文或规范化文本，右侧切换“归纳 / 我的理解 / 关联 / 版本”。头部展示作者、来源、发布时间（可未知）、收集时间、原件类型、处理策略和读取状态。

知识卡包含中心问题、主要观点、关键证据、局限、与既有知识的联系。每条证据按钮打开原文定位：段落、Markdown 行号、视频时间戳或 GitHub commit。用户笔记有独立背景与作者标记。

修改标题、主题或备注不改变原件。更新文件/重抓正文新增 source revision，归纳列表可对照两个版本。移除素材进入回收站；详情先展示会影响哪些 Report/博客/图书馆引用。

## 6. Report 阅读页

顶部固定显示日期、时区、截止时间、版本、状态；次行显示 `处理 16/20，受限 2，失败 1，晚到 1`。分母口径链接到本次输入清单。

内容默认分为“今日重点 / 主题 / 博客素材 / 待验证”。右侧证据抽屉在点击引用后打开；不默认遮住正文。每个主题可展开全部素材，阅读重点后即可判断哪些值得深读。

底部操作：“采纳为选题 / 合并到已有选题 / 添加个人注释 / 导出”。对没有证据的候选项禁用生成完整文章，提供“补证据”；已有有限证据可生成带缺口的草稿。

状态与文案：

| 状态 | 读者看到 | 下一步 |
| --- | --- | --- |
| 未生成 | 今天已收集 N 项，待整理 | 生成 Report；无输入时先收集 |
| 正在生成 | 已整理 N/M，截止时间被冻结 | 继续阅读既有版本，可取消当前任务 |
| 部分完成 | 可读内容已保存，3 项未处理 | 看正文、重试失败项、查看来源 |
| 无更新 | 预期来源均检查成功，本期无新素材 | 看复习或选择历史 Report |
| 全部失败 | 本次未形成有效 Report | 错误详情；重试/配置模型 |
| 有新版 | v2 已生成，保留 v1 | 查看差异，不自动改变当前阅读版本 |
| 有晚到素材 | 2 项不在 v1 中 | 更新本日或等待下一期补录 |

Report 内手动批注绑定稳定区块 ID。新版不能复用相同 ID 表达不同观点；无法对齐的批注留在旧版并提示迁移。

## 7. 主题与写作台

主题页包含“关注问题 / 素材 / 选题 / 博客 / 图书馆关联”。不是把同标签文件平铺在一起；最上方显示“已有结论 / 新变化 / 待验证”，帮助形成研究路线。

写作台使用三栏：左侧选题和大纲，中间编辑器，右侧证据/AI 建议。首版 Markdown 编辑与预览；后续富文本必须无损保留 fenced code、表格、链接和 frontmatter。

选题卡显示中心问题、证据数量、个人理解缺口、系列归属和进度。主要操作“开始写作”，创建 draft；不会把 Brief 卡片标成文章已经完成。

AI 操作按范围呈现：“生成大纲”“扩写选中章节”“列出反例”“校验引用”。生成结果先在建议栏显示 diff，用户选择采纳。正在编辑时服务器出现新版本，提示“内容有更新，选择比较”，不自动刷新编辑器。

用户离开时优先自动保存人工草稿；保存失败显示“仅本机保留”并可重试。采纳、归档、导出都显示精确 revision；导出包包含正文和引用清单。

## 8. 图书馆与复习

图书馆首页展示书架与最近修改条目。书页采用章节目录 + 正文，不要求学习图数据库交互才能阅读。概念关系作为正文链接与右侧关联列表。

整合提案显示目标章节、变化类型、依据博客、内容 diff、受影响链接。采纳形成新知识版本；拒绝记录理由，取消只撤销提案，不删除来源博客。

复习页一次一个条目：先展示问题，让用户尝试解释，再展开要点与来源。按钮“能解释 / 还模糊 / 忘记了”，下方显示新的复习日期。每天默认最多 5 条，其余顺延；没有“逾期债务”红色大计数。

`needs_review` 图书馆条目顶部写“原结论可能需要更新”，展示冲突证据。仍可读旧版，但检索问答不得把它作为无条件的当前结论。

## 9. 关注来源与设置

每个来源显示名称、类型、关注问题、下次开始时间、最近成功、连续失败、抓取能力、授权范围。状态包括运行、暂停、需重新连接、部分能力受限。

连接流程：选来源 → 配置关注范围 → 查看会获取的内容 → 试采集 → 保存/启用。配置保存与日程启用分开；成功测试不自动启用持续任务。

模型设置显示 provider、模型、可发送的敏感等级、每日费用/token 上限、单任务预算、本机或远端处理方式。默认拒绝向未授权 provider 发送私人笔记；一次性允许与持久规则区别明确。

日程设置直接展示“每天 21:30 · Asia/Shanghai”，附下一次执行的日期与时区。来源更新周期和 Report 时间分别配置；Server 停机时显示停机/未知，不将浏览器离线当作服务停机。

## 10. 快捷键、可访问性与交互规则

`Cmd/Ctrl+K` 搜索与命令；`Cmd/Ctrl+Shift+N` 收集；编辑器 `Cmd/Ctrl+S` 保存草稿；`Esc` 关闭抽屉并返回触发按钮。常用控件可完全通过键盘访问。

新增/更新成功用短消息并带返回对象链接。失败用可操作文案，例如“来源需要登录：可粘贴正文”，开发细节折叠到详情。不使用虚假的精确百分比，只有已完成/总量已知时才显示进度。

长任务有独立 job ID；取消后显示已保存内容的范围。选择/筛选不触发生成，阅读不自动采纳，标签调整不启动全文重写。

移动端触控区域最小 44px；正文不依赖 hover；对比度验证、焦点样式、屏幕阅读器标签和 reduced motion 纳入验收。

## 11. 设计验收

用户能够在 10 秒内保存一个链接；在今日页直接找到素材与 Report；用两次点击以内看到任意事实的来源；能分辨 AI 推断与本人观点；能找到部分失败和晚到输入；能恢复上一版文章；在 390px 宽度下完成收集和阅读。

以上是交互契约。本轮没有实现界面或创建定时任务，后续 UI 原型应使用清楚标记的演示数据，再进入真实内容闭环。
