# 分布式 K-means：单机多进程设计与实验

## 1. 目标和范围

用一个协调进程与多个常驻工作进程，复现 K-means 的数据并行计算逻辑：
固定分片、广播中心、局部统计、全局归约、同步屏障与迭代收敛。
这里的归约是把各分片的统计量合并；屏障是当前轮所有分片完成后才进入下一轮。

首版使用 NumPy 和 Python 标准库 `multiprocessing`，放在现有 pylab 中。
串行版本提供对照，多进程版本必须真的启动独立进程，而不是用循环冒充并行。
只使用确定性合成数据，不需要密码、API key、企业数据、第三方账号或外部服务。

不实现跨机器传输、自动重试、节点替换、持久化恢复、GPU、异步 K-means 或 K-means++。
不修改已有 Daft 实验；本实验也不代表 Daft、Ray 或 Spark 的运行结果。
首版只验证同步算法及进程通信语义，不声称生产可用、集群容错或分布式性能收益。
Lloyd 算法的收敛也不保证全局最优；计算等价与聚类质量必须分别验收。

## 2. 算法与数据所有权

输入 X 的形状为 N×D，中心 C 的形状为 K×D，均使用 float64。
初始化只在协调进程执行一次：固定种子 42，从样本中无放回抽取 K 个初始中心。
所有对照运行共享完全相同的数据和初始中心，而不是分别重新初始化。
等距时选择编号最小的中心；空簇保留上一轮中心；空分片返回零统计量。

工作进程 w 在轮次 t 中计算：

- 每个样本距离最近的中心编号。
- `sums[j]`：分配给簇 j 的所有样本的坐标和。
- `counts[j]`：分配给簇 j 的样本数量，int64。
- `sse_before_update`：到本轮旧中心的距离平方和。

协调进程按分片编号固定顺序相加，更新 `C[j] = total_sums[j] / total_counts[j]`。
不能对局部中心直接取平均：分片 `[0]` 与 `[10, 10, 10]` 的共同中心是 7.5，不是 5。
每轮必须满足 `sum(total_counts) == N`，并验证所有数值有限。

停止条件是所有中心的最大欧氏位移不超过 1e-6，或者达到 100 轮。
达到轮数上限仍未收敛时返回 `converged=false`，不能标成已收敛。
结束后在协调进程重新分配全部样本，得到与最终中心对应的 labels、counts 和 SSE；
这一步单独计时，不能把上一轮旧中心的 SSE 当成最终 SSE。

## 3. 执行结构与通信协议

```text
                     协调进程
       数据一次性分片，显式 spawn 工作进程
              /          |          \
          worker 0    worker 1    worker P-1
          固定 X0      固定 X1      固定 XP-1
              \          |          /
                   ready 屏障
                         |
       广播 (round_id, centers)，不广播原始 X
                         |
         每个 worker 返回 sums / counts / SSE
                         |
      校验轮次与分片 → 按编号归约 → 更新中心
                         |
               收敛或下一轮；最后回收进程
```

每个工作进程使用专属双向 Pipe，不使用可能把分片调度到不同进程的通用任务池。
进程启动参数只包含该进程的数据分片，启动时序列化一次；启动完成后只收发小消息。
使用显式 `spawn`，不依赖 Linux 的 fork 继承内存行为。

| 消息 | 字段 | 约束 |
| --- | --- | --- |
| ready | shard_id, pid | 一条连接绑定一个分片与实际 PID |
| step | round_id, centers | 当前轮全部工作进程看到同一个中心快照 |
| stats | round_id, shard_id, pid, sums, counts, sse, compute_seconds, delay_seconds | 与预期轮次/分片/PID 一致，形状正确，计数守恒，数值有限 |
| stop | 消息类型 | 正常完成后关闭工作进程 |

每轮收齐 P 个分片后才更新中心；重复分片、错误轮次或缺失结果不能参与归约。
没有重试，因此不需要持久化去重表，也不能在异常后用部分分片继续计算。
Pipe 和 pickle 仅用于本程序自己启动的可信子进程，不接受外部发送者或网络数据。

工作进程异常退出、连接关闭、协议错误或接收超时，整次计算失败，不生成成功结果。
启动等待与计算轮次等待分别限时；默认每轮 30 秒，故障实验用更短的轮次等待。
失败时只终止本次创建的工作进程，join 后仍未退出才升级为 kill；不扫描或终止其他任务。
正常路径也要验证进程已退出；KeyboardInterrupt 同样必须进入清理路径。
教学规模限制为最多 32 个工作进程、200 万个输入标量、1024 个中心标量，避免无意放大。
接收截止时间不等于对操作系统进程启动、序列化或 Pipe 写入的严格实时保证。

## 4. 复杂度、内存与观测口径

每轮总计算量 O(NKD)，理想情况下每个工作进程承担 O(NKD/P)。
广播与归约的总数值量 O(PKD)，协调进程可能成为中心数量很大时的瓶颈。
每个工作进程分批计算距离，距离中间数组不随 N 一次性增长；基础批次为 1024 行，
再按 K×D 自动缩小，限制单个距离差中间数组不超过约 8 MiB。
协调进程保留原始 X 用于串行基线和最终评估；工作进程另持有分片副本。
这不是共享内存或零拷贝实现，启动时总内存至少包含约两份输入，另有序列化和运行时开销。
10 倍数据首先增加输入内存和扫描时间，不会把每轮统计消息增大 10 倍。
本版不做 SIMD 指令、缓存命中率或 NUMA 优化，也不对它们作性能结论。

每次运行记录环境版本、CPU affinity（可用时）、数据和代码 SHA-256、初始中心，
以及以下指标：

- startup_seconds：创建进程到所有 ready 返回，包括启动与初始数据搬运。
- 每轮 worker compute_seconds：局部数值计算，不含人为延迟与回复写入。
- delay_seconds：明确记录的注入延迟，不解释成真实网络耗时。
- round_seconds：协调端发出本轮请求到得到新中心的时间，含通信和等待。
- reduce_seconds：收齐统计量后校验、归约和更新中心的时间。
- 每轮发送/接收的 pickle 消息字节数：实际序列化 payload 大小，不含 Pipe framing、
  操作系统复制、进程启动参数和真实网络协议；初始输入只另记数值数组字节数。
- evaluation_seconds、shutdown_seconds、total_seconds 分开记录。
- 实际 worker PID、退出码、各分片行数、中心位移和旧中心 SSE。

各进程的计算时间与通信可能重叠，不能将它们相加当成总墙钟时间。
本轮实验不清系统缓存、不修改全局线程配置、不发布跨机或框架性能排名。

## 5. 实验矩阵与通过条件

默认 N=10000、D=2、K=3，三团相互分离的高斯合成点，seed=42。

| 实验 | 目的 | 通过条件 |
| --- | --- | --- |
| 串行、2 进程、4 进程 | 分片计算等价与真实进程执行 | 同初始中心，最终中心/SSE 在容差内相同，分离数据标签相同，PID 独立且常驻 |
| 4 进程不均匀分片 | 验证按数量加权归约 | 行数按 70%/10%/10%/余量分配，结果仍与串行一致 |
| 4 进程慢 worker | 观察同步屏障 | worker 0 首轮注入 0.2 秒延迟，结果不变，首轮时间覆盖注入延迟 |
| 工作进程退出 | 失败传播 | 首轮 worker 0 非零退出，协调端明确失败并回收全部自有进程 |
| 错轮回复 | 协议约束 | 首轮 worker 0 返回错误 round_id，不能进入归约 |
| 超时 | 截止时间与清理 | ready 完成后首轮延迟 2 秒，轮次等待 0.1 秒，明确计算轮次超时且无遗留进程 |
| 初始化对照 | 区分计算等价与聚类质量 | 同一输入另取每个已知合成组的首个点初始化，记录 SSE，不把它当成通用初始化器 |

中心使用 rtol=1e-6、atol=1e-8 比较；浮点加法顺序不同，不要求逐比特一致。
只对远离中心分界线的合成数据要求最终标签完全相同，不泛化到临界等距样本。
还需手算小样本作为独立判据，防止串行和多进程共用同一错误内核仍“对比通过”。
单元测试覆盖：不等大小分片、空分片、空簇、重复点、K=1、K=N、等距选择、
非法 K/维度/预算/超时、NaN/Inf、浮点溢出、达到迭代上限、重复/缺失/错轮统计、
异常退出、超时清理、启动失败和中断清理、输入放大不增加广播消息大小，
以及最终 labels/SSE 与最终中心一致。验收门槛不能因 `python -O` 而被关闭。
