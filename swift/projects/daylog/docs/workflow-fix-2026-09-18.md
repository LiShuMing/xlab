# 中等优先级工作流修复

范围：原始测试报告中的两个 P2——编辑后的状态撤销、私人日记草稿阻塞工作回顾。沿用现有 C3 界面与 schemaVersion 1，不改变数据库结构。

## 状态撤销保留后续内容

以前用任务整体 revision 约束撤销，后续任何标题、说明编辑都会触发冲突。现在 `AppStore.changeStatus` 保存状态事件 ID，`Workspace.canUndoStatusChange` 检查它是否仍是该任务最近一次状态变化；普通编辑不影响撤销资格。

`Workspace.undoStatusChange` 从当前任务开始，只还原该事件之前的 status 和 lastOpenStatus。标题、说明、步骤保留，revision 递增，并记录新的 before/after 事件。撤销已完成任务的重新打开操作时，也保留原先的恢复状态语义。

- 正在输入标题/说明时点击撤销，先提交文字缓冲；文字无效时保留输入并显示校验错误。
- 连续切换状态，撤销最近一次；重复选择当前状态不创建无效撤销记录。
- 其他入口发生新的状态变化，旧撤销入口失效并移除；即使状态绕一圈回到相同值，也不允许重放旧撤销。
- 跨日撤销先冻结前一天快照，不改写历史。

## 回顾只受相关工作草稿影响

`AppStore.reviewBlockingReason(dayIDs:)` 替代回顾流程中的全局未保存检查。生成和草稿失效判断使用同一范围规则：

| 未提交内容 | 对回顾的影响 |
| --- | --- |
| 个人日记、模型输出编辑 | 不阻塞生成或使来源失效；它们不属于模型输入 |
| 新任务、菜单栏新增、今日重点、工作随记、进展 | 回顾范围包含今天时阻塞，并提示保存对应内容 |
| 标题/说明、步骤 | 任务出现在回顾范围内尚未归档的计划时阻塞 |
| 已归档日期之后的任务编辑 | 不影响使用冻结快照的历史回顾 |

`Workspace.reviewSource` 仍排除 personal 和 summary；未提交输入不会被加入提示词。全局 `hasUnsavedChanges` 继续保护正常退出和备份恢复，生成回顾不会清空私人草稿。实际工作来源改变后，草稿仍失效，领域层也拒绝采纳。

## 自动回归

`./scripts/check-workflows.sh` 将生产领域、服务和 AppStore 源码编译为独立检查程序；不读取用户日记和凭据，不联网。生成器依赖可以注入，生产默认仍调用现有 LLMClient；测试捕获实际发送边界的提示词。

新增 30 项断言，覆盖撤销后文字与步骤保留、未提交文字、无效文字保护、无操作状态选择、连续状态变化、其他入口失效、状态往返、跨日快照、真实 SQLite 重新打开、私人内容隔离、输出编辑与采纳、七类工作草稿、历史回顾范围和来源过期拒绝。

完整 `./scripts/check.sh` 已纳入这些断言；原有 19 项核心检查、20 项保存队列检查及普通/超过 50 MB 工作空间的跨进程 SQLite 检查继续执行。持久化比较遵循现有 v1 JSON 的整秒时间精度。

2026-09-18 执行结果：完整检查通过（19 + 20 + 30 项断言，以及普通/大文档跨进程 SQLite 检查）；Release 构建和 ad-hoc 签名校验通过。本轮日志在本机 `build/qa/p2-checks.log` 与 `build/qa/p2-build.log`，构建产物不纳入源码。

## 原生窗口复测

使用独立 `app.daylog.qa` Bundle 和 `--demo` 内存工作空间：

- 进行中任务完成后修改标题，再点击“撤销状态修改”：恢复进行中，新标题与步骤保留，撤销按钮消失，无冲突提示。
- 私人日记输入 34 字而不保存，切到回顾，读取既有模型配置后点击生成：出现“整理中…”和取消按钮，不再出现未保存草稿阻塞。
- 本轮真实模型请求在等待期间主动取消；回到日记页，34 字草稿完整保留。生成结果和采纳分支由上述注入生成器的自动回归验证，本轮不声称真实模型生成/采纳已完成。
- QA 已退出；正常应用确认无未提交内容后重启至新版，显示本机保存状态。测试没有向真实日记写入任务或私人内容。

## 边界

撤销仍为当前会话最近一次状态操作，不提供多级撤销栈。私人日记草稿仍只在内存，崩溃恢复与统一保存入口是独立后续工作。完整 Xcode UI 自动化及旧版 macOS 兼容性仍待专项验收。
