## 2. 对上一版 C 的调整

### 窗口层级

保留窄导航和任务/详情分栏，减少大号英文装饰与虚构任务编号。顶部工具栏负责全局操作“新建待办”和“今日回顾”；中心负责当天任务与工作记录；右侧负责当前任务的编辑上下文。

窗口采用中性表面、细分隔线、低饱和铜色强调。选中行有浅背景和细侧边标识。标题、辅助信息与编辑属性形成明确层级；在小屏上详情落到下方，原生版计划使用独立详情页或 sheet。

### 今日任务分组

按以下优先顺序唯一归组：

1. 已完成 → 已完成组。
2. 进行中 → 进行中组；若安排在收尾时，行内仍显示该安排。
3. 待开始且安排在收尾时 → 收尾时组。
4. 其他待开始事项 → 接下来组。

行内显示分类与步骤完成数。分类只是样例元数据，不引入项目管理层级。主任务状态与步骤清单相互独立：完成全部步骤不会擅自将任务标记完成。

### 右侧详情

标题可编辑；状态支持待开始、进行中、已完成；安排支持今天、收尾时。备注可持续修改；步骤可勾选、新增；进展可单独追加。

追加进展同时出现在该任务的进展记录和当天工作记录。真实模型应使用带 taskID 的一条记录被两个视图引用，不能复制成两条导致总结重复。原型为独立内存结构，仅演示双处可见的效果。

状态修改提供一次撤销。用户勾选完成再撤销时恢复原先的待开始/进行中状态，避免一律退回待开始。

### 日级回顾

“今日回顾”属于当天，不从所选任务决定总结范围。它在右侧占用独立面板，与任务详情切换；生成前能看见范围，生成后可编辑并主动采纳到工作记录。

原型仅采用本地规则，读取当前任务标题/状态、今日重点及普通工作记录；不请求模型。草稿不读取个人日记，生成时也排除已采纳的总结，避免总结递归膨胀。

草稿生成后，任务/备注/步骤/重点/工作记录变化都会标记来源过期并禁用采纳。切换选中任务不会标记过期。重新生成会替换当前草稿；正式实现需要在用户已编辑草稿时提供保留或覆盖选择。

## 3. 设计稿已覆盖的操作

- 新增、完成、撤销、修改标题与状态、安排到收尾时。
- 任务步骤新增/勾选、任务备注编辑、追加进展。
- 普通工作随记新增，进展双处呈现。
- 日级回顾生成、编辑、采纳、防重复采纳、来源过期提示。
- 历史展开和独立个人日记编辑；历史为固定示例。
- 收起/显示详情、任务行上下切换、Space 开关预览、Escape 收起。
- 在原型聚焦且不处于输入状态时，N 聚焦新增任务；不注册全局快捷键。
- 设计面板切换浅深外观、任务密度、宽窗口详情宽度。

演示数据只在页面内存保留；没有数据库保存、真实通知或模型调用。设计稿未进行浏览器自动化或原生系统集成测试；不能由页面交互推断生产行为已经实现。

## 4. 对原生模型的增量建议

这些字段是本轮 UI 对实现的建议，正式编码前评估是否纳入首版：

- `TaskStep`：UUID、taskID、text、isDone、sortIndex；步骤变更纳入修订号。
- `DailyPlanItem.daySection`：day / closing，属于某一天的计划，不挂在跨日任务上。
- `JournalEntry.taskID`：可空，用于关联任务进展；一条记录支持双视图展示。
- `JournalEntry.origin`：manual / taskProgress / acceptedSummary，用于生成输入去重。
- `SummaryDraft.sourceRevision` 与选定来源 ID：真实接入模型时做输入范围与过期校验。

原型为了精简将 slot 存在任务对象上，不应直接照搬到持久化模型。原生 UI 采用窄导航 + HSplitView、List selection、TextEditor、Form 和系统 Commands；该选择保留 C 的窄导航，详见 [技术设计](technical-design.md)。宿主网页中的外观近似不规定原生控件必须逐像素复制。
