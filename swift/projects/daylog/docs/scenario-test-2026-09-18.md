## P2-01：提醒时间草稿切页后无提示丢失

复现：设置 → 开始工作从 `09:30` 输入 `10:15` → 不点击“保存时间” → 今天 → 设置。

观察：字段恢复 `09:30`。编辑时底部没有“有未提交编辑”，离开也没有提示。用户临时去看任务再回来，必须重输时间；与工作日记草稿跨页保留的行为不一致。保存按钮是显式的，因此这不是已保存设置丢失，而是未提交设置草稿缺乏保护。

代码：`DayLog/Features/HistoryJournalSettings.swift`，`SettingsView` 的 `@State morning/evening` 和 `.onAppear` 从存储重载；`AppStore.hasUnsavedChanges` 不包含这两个字段。

建议：设置草稿由共享状态管理，变化后展示待保存状态；切页保留，退出时一起保护。验收应覆盖切页、关窗重开、取消修改、正常退出；未点击保存时不能自动改变实际提醒排期。

## P2-02：“完整备份”成功提示没有说明遗漏未提交输入

复现：私人日记输入 `SCENARIO_PRIVATE_DRAFT`，工作随记输入 `SCENARIO_WORK_DRAFT`，均不提交 → 设置 → 完整 JSON 备份 → 保存。

观察：正常弹出保存面板并显示“导出完成”。实际文件有 4 个任务、1 条记录、1 个生成草稿，但两份输入标记均不存在。私人草稿后来仍保留在 UI，说明本次不是输入被删除，而是导出范围未涵盖屏幕上的草稿。用户若把“完整备份”当成换机或退出前保障，会高估恢复范围。

证据：[实际备份](../qa/evidence/2026-09-18-scenarios/draft-omission-backup.json)、[内容检查结果](../qa/evidence/2026-09-18-scenarios/backup-inspection.json)、截图 05、07、08。

代码：`DayLog/App/AppStore.swift` 的 `export(json:)` 直接捕获 `state`，未检查 `hasUnsavedChanges`；输入缓冲不属于 Workspace。现有备份仍正确覆盖已经提交的内容。

建议：导出前明确显示未提交内容清单，提供“保存后导出”和“仅导出已保存内容”；如决定把草稿纳入恢复，需先定义格式和恢复语义，不能偷偷把私人草稿提交为正式日记。验收需比较导出/恢复后的内容，并验证用户选项与提示一致。

![有未提交编辑时仍显示导出完成](../qa/evidence/2026-09-18-scenarios/08-backup-success-with-unsaved-drafts.jpg)

## P2-03：隐藏在其他任务中的草稿难以找到

复现：任务 A 的“进展”输入文字但不提交 → 选择任务 B → AI 回顾 → 生成。

观察：弹窗只说“请先保存工作记录或进展，再生成或采纳回顾”，只有“好”按钮。当前界面没有 A 的草稿位置，任务列表无草稿标记。退出时的“返回保存”也只是回到原来的历史页，不定位未保存输入。数据保护是正确的，但用户需要自行逐个任务查找。

代码：`AppStore.reviewBlockingReason(dayIDs:)` 仅返回字符串，未携带任务/编辑器标识；`WorkspaceView` 错误弹窗仅提供关闭动作；`AppDelegate.applicationShouldTerminate` 不导航到待保存项。

建议：提供统一草稿列表，显示类型、任务标题与“去保存”；任务行显示未提交标记。回顾阻塞与退出提示共用此入口；Cmd+S 保存可明确提交的输入，并单独处理非法输入，不能默默丢弃。

## P3-01：模型 Markdown 在阅读态仍原样显示

真实模型返回包含 `**已完成**` 和列表标记的文本。编辑时原始文本合理，但采纳后的详情、今日工作记录和历史页仍直接显示这些标记，较长回顾挤占列表且不易浏览。该体验缺口在原报告中曾由代码指出，本轮有真实输出和截图证据。

代码：`ReviewView`、`TodayView`、`HistoryView` 对动态字符串使用 `Text(draft.text)` / `Text(entry.body)`。

建议：输出编辑与阅读分开；阅读态安全渲染 Markdown，长回顾默认摘要并可展开。保留原始文本作为编辑与导出来源。优先级低于草稿保护和备份范围。
