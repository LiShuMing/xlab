**当前决定：用户已选择“刻白”和 K 形图标，并要求亮色界面。** 本文保留前期命名探索；已落地 [晴白主题](kebai-daylight-theme.md)。以下 A/B/C 的推荐关系属于历史提案，不再作为当前命名建议。

2026-09-20 · 第一轮探索，检索修订版 v2，未定稿。用户认为 DayLog 名称缺乏品牌感，且应用没有图标。当前名称、Bundle ID 和用户数据路径尚未改动。

## 命名依据

产品核心是“安排今天 → 随手记录进展 → 回顾”，后续可延伸主题订阅与调研。品牌要能表达记录和整理，不局限于日记，也不把 AI 当作唯一卖点。现有 Graphite Studio 的石墨灰、铜色和安静工作台作为视觉起点。

首轮采用两个汉字的中文主名，拉丁字母转写作为辅助识别；转写不是已经确定的国际品牌名。

| 方向 | 名字 | 含义与适配 | Logo 构思 | 取舍 |
| --- | --- | --- | --- | --- |
| A · 推荐 | 序迹 / XUJI | 给工作以秩序，让进展留下轨迹；可覆盖任务、日记与调研 | 一条连续折叠纸带；石墨底、米白正面、铜色折面 | 品牌故事最完整；小尺寸时须进一步简化折面 |
| B | 刻白 / KEBAI | 记录此刻，也为思考留白 | 两片错位的几何书页，中央负空间；暖白底、石墨实体 | 最安静、建筑感最强；初次看到名称不容易猜到功能 |
| C | 日隙 / RIXI | 收集一天间隙里的工作片段 | 被一道留白切开的日轮；灰蓝底、暖铜色 | 更温暖、有日常感；图标需避免被误认为天气应用 |

当时建议先选 A 的名称与识别符号，现已由用户选择的“刻白”替代。A 的探索短文案为“让每一天，有迹可循。”；功能说明用“任务、随记与每日回顾”。A 的纸带代表连续积累，不作为姓名首字母。软件中的栏目继续用“今天、历史、日记”，无需改成抽象品牌词。

## 工具与产物

1. **imagegen**：对比名字、核心图形与材质；当前已交付此阶段。
2. **矢量编辑**：选定方向后重建几何结构，交付可编辑 SVG、黑白 Logo 和分离的背景/前景层。可以使用 Figma 或其他矢量工具；不要求安装插件才能评审当前稿。
3. **Icon Composer**：将分层图形做成 macOS 图标并预览外观，交付 `.icon`。本机 Xcode 内已找到 1.6 版，Info.plist 声明最低 macOS 15.3；官方独立下载页当前要求 macOS 26.4，不能把下载页要求直接套用到本机已有版本。最终图标的导入和编译兼容性需实际验收。
4. **兼容资产**：为 macOS 14/15 及当前 SwiftPM 打包链提供传统 `AppIcon.appiconset` / `.icns`，并与现代分层版本对照。
5. **Xcode 与原生运行**：在 Dock、⌘Tab、Finder、菜单栏和深浅色背景下检查。菜单栏优先在实际 16/18/22 pt 下检查，Dock 额外观察 32/64/128 px，不能只看 1024 px 大图。

依据 [Apple App Icons 指南](https://developer.apple.com/design/human-interface-guidelines/app-icons/)，核心形状保持简单，不把完整产品名放进图标；现代分层资产提供未预裁圆角的方形画布，由系统处理遮罩。展示稿中的圆角方块仅模拟成品效果。Icon Composer 支持分层材质与外观预览，见 [官方介绍](https://developer.apple.com/icon-composer/)。

## 与当前工程的衔接

定稿后需同时覆盖两条构建路径：

- `project.yml`：添加图标资源，配置 App Target 的图标名称；当前 `DayLog/Resources` 被排除，不能只把图片丢进去就认为接入成功。
- `scripts/build-app.sh` 与 `DayLog/Resources/Info.plist`：复制传统 `.icns` 并声明图标，使 SwiftPM 打包版也能显示。
- App 显示名、菜单、窗口标题、设置文案与导航顶部符号同步调整。开发版增加 Dev 后缀。
- 首次品牌迭代保留现有 Bundle ID、SQLite 数据目录和 Keychain service，避免改名后看起来“数据消失”。Swift Target 和目录名可保持 DayLog，独立于用户可见名称。

本轮对“序迹”“刻白”“日隙”的网页检索未找到明确的同名同类应用，但搜索覆盖有限；这不是名称、商标或域名可用性的确认。名称定稿前再做针对目标发布地区的重名核查。
