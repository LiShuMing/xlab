# 时间线段树 + 可回滚并查集

这是一个离线动态连通性的教学例子：图从空图开始，支持 `ADD u v`、
`REMOVE u v`、`QUERY u v`。目标不是让并查集学会删边，而是改变执行顺序，
使每条边只需被加入、再按栈顺序撤销。

## 先运行，再看代码

在 xlab 根目录运行（C++17，无第三方依赖）：

```sh
make -C cc/algo/src/oi demo
make -C cc/algo/src/oi test
```

二进制为已被忽略的 `cc/algo/bin/oi_segment_tree_rollback_dsu` 和对应的 `_test`。
演示输出完整执行轨迹，测试默认不打印轨迹。
不需要启动服务器，也不读写外部数据。

建议按以下顺序阅读：

1. [演示入口](oi_segment_tree_rollback_dsu.cc)：9 个操作和手算答案。
2. [核心实现](offline_dynamic_connectivity.h) 的 `RollbackDsu`：只记录真正发生的修改。
3. 同一文件的 `collectLifetimes()`：把加边、删边配成生存区间。
4. `insert()`：把生存区间放入时间树，而不是在这里修改并查集。
5. `dfs()`：保存、应用、递归、恢复四步。
6. [测试入口](oi_segment_tree_rollback_dsu_test.cc)：独立 BFS 参照和边界测试。

本例与既有练习统一放在 `cc/algo/src/oi/`，目录内 `.cc` 一律使用 `oi_` 前缀，
既有的 `oi_data.cc` 等文件保持不动。

## 1. 时间到底表示什么？

顶点 `0=A`、`1=B`、`2=C`；时间从 0 开始，每条操作占一个时间点。
叶子 `[t,t+1)` 表示执行第 t 条操作后的图。所有区间统一左闭右开。

| t | 操作 | 执行后活跃边 | 查询答案 |
| --- | --- | --- | --- |
| 0 | ADD 0 1 | 0-1 | |
| 1 | ADD 1 2 | 0-1、1-2 | |
| 2 | QUERY 0 2 | 0-1、1-2 | YES |
| 3 | REMOVE 0 1 | 1-2 | |
| 4 | QUERY 0 2 | 1-2 | NO |
| 5 | ADD 0 2 | 1-2、0-2 | |
| 6 | QUERY 0 1 | 1-2、0-2 | YES |
| 7 | REMOVE 0 2 | 1-2 | |
| 8 | QUERY 0 1 | 1-2 | NO |

先读完整个操作序列，才能知道每条边什么时候消失：

```text
0-1： [0,3)       不能包含删除时刻 3
0-2： [5,7)
1-2： [1,9)       输入结束还没删，右端点取 T=9
```

这一步就是“离线”。在线场景若不知道未来的删除时间，不能直接使用本实现。

## 2. 线段树里存的不是和，而是边列表

时间树根为 `[0,9)`。每个节点递归从中间分成两段，直到长度为 1。
将一条边的生存区间拆成互不相交的规范节点；遇到完整覆盖的节点就存边并停止下降。
演示中的实际存放位置是：

```text
0-1：[0,3) = [0,2) + [2,3)
0-2：[5,7) = [5,6) + [6,7)
1-2：[1,9) = [1,2) + [2,4) + [4,9)
```

例如 `1-2` 在 `[4,9)` 存一份，就能供这个节点的全部后代使用。
不用在每个叶子重复存，也不用像区间求和那样 `push_up` 合并答案。

同一条生存区间虽然可能存多份，但规范节点彼此不相交；对于任意有效时刻 t，
根到叶子 t 的路径恰好经过其中一个节点。区间之外的叶子则一个也不会经过。

## 3. DFS 是如何维护正确状态的？

每个节点都执行相同的四步：

1. **保存**：`checkpoint = dsu.snapshot()`，记住修改栈长度。
2. **应用**：加入本节点的边，祖先节点加入的边仍然保留。
3. **递归/回答**：先访问左子树，再访问右子树；叶子上的 QUERY 读取当前 DSU。
4. **恢复**：`dsu.rollback(checkpoint)`，使 parent、size、连通块数回到进入前。

关键不变量：**处理叶子 t 时，并查集的连通关系等于 t 时刻全部活跃边的连通关系。**
这不要求 DSU 保存每条边的实体；形成环的冗余边可以不改变 DSU。

特别留意轨迹中这一段：

- 进入 `[4,9)`，应用 `1-2`：B、C 连通，A 仍独立。
- 到叶子 `[4,5)`，没有 `0-2`，所以 `QUERY 0 2 => NO`。
- 到 `[5,6)`，暂时应用 `0-2`，离开时撤销；祖先的 `1-2` 仍保留。
- 到 `[6,7)`，重新应用 `0-2`，所以 `QUERY 0 1 => YES`。
- 离开 `[6,7)` 后撤销 `0-2`；到 `[8,9)` 时 A 又独立，答案是 NO。

可见 DFS 不是简单沿时间轴持续加边。它会为了进入另一个分支，先恢复共同祖先状态，
再加入新分支需要的边。这里允许改变加边顺序，是因为连通性只取决于活跃边集合。

## 4. 怎样读执行日志？

| 标记 | 含义 | 应观察的内容 |
| --- | --- | --- |
| EDGE | 生存区间 | 删除时刻不包含在区间中 |
| STORE | 实际存放节点 | 同一生存期的节点范围互不相交 |
| ENTER | 进入 DFS 节点 | snapshot 是进入前的栈长度 |
| APPLY | 真正合并两个连通块 | 栈长加 1，components 减 1 |
| SKIP | 两端已连通，无须修改 | 栈长不变，自环也会走这里 |
| QUERY | 读取叶子答案 | 不应改变 parent/size |
| ROLLBACK | 恢复进入前的状态 | undo 是撤销的真实修改数，不是访问的边数 |

日志缩进代表递归深度。`parent` 打印原始父指针，`size` 只有根节点处有效。
演示最后的根节点 ROLLBACK 应恢复成三个独立点。
`SKIP` 的专门演示可看测试中的自环；本例主操作表本身不含环。

## 5. 为什么不做路径压缩？

普通并查集为了加速 find，会沿路改写父指针。回滚并查集需要知道发生过的每次写入，
若 find 也改写，就必须额外记录这些修改，并重新分析回滚后的复杂度。

本例选择更简单的约束：find 严格只读，仅按大小合并。小树挂到大树下时，
小树中任意节点所在集合至少翻倍，所以树高最多 O(log N)。

一次成功合并只改 `parent[small]`、`size[large]` 和连通块数，记录一条 Change 即可。
一条冗余边不修改任何字段，因此不压栈。恢复 snapshot 可以自然处理这种 no-op，
不会误把祖先节点的有效合并撤掉。

## 6. 测试覆盖与复杂度

测试包含手算的 YES/NO/YES/NO、空操作序列、没有 QUERY、单点、自环、三角形、
删除后重加、反向端点、未删除到结束的边、嵌套 snapshot、完整字段恢复和多次 solve。
非法端点、重复添加活跃边、删除不存在的边、非法操作类型和未来 snapshot 均应抛异常。
另外用固定种子 `20261107` 生成 500 组合法操作流，逐条对比独立的“活跃边集合 + BFS”。
测试采用会抛异常的 require，不依赖可能被 `-DNDEBUG` 关闭的 assert。

还可以强制重编译，分别验证发布模式和 AddressSanitizer/UndefinedBehaviorSanitizer：

```sh
make -C cc/algo/src/oi -B CXXFLAGS='-std=c++17 -O2 -DNDEBUG -Wall -Wextra -Wpedantic' test
make -C cc/algo/src/oi -B CXXFLAGS='-std=c++17 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer' test
```

`-B` 避免 Make 复用以旧编译选项生成的二进制。Sanitizer 需要本机编译器支持。

设 N 为点数、T 为操作数、M 为边生存区间数、Q 为查询数。关闭 trace 时：

- 区间配对：使用有序 map，为 O(T log(M+1))。
- 区间分配：每个生存区间存 O(log(T+1)) 份。
- DFS 加边：每次 unite 最坏 O(log(N+1))，每条实际修改回滚 O(1)。
- 总时间：O(N + T log(M+1) + M log(T+1) log(N+1) + Q log(N+1))。
- 总空间：O(N + T + M log(T+1) + Q)。当前栈最多保留 N-1 次成功合并。

trace 额外打印原始数组，每个状态 O(N)，不应拿开启 trace 的运行时间做算法基准。
本实现是严格的单份无向边语义，不支持平行边引用计数、初始非空图或在线输入。
它只回答连通性，不能直接据此判断二分图；二分图还需要维护端点异色约束。
