## 学习方式

每天围绕一个能解释、能定位源码、能验证的问题展开。深入一个主项目，挑一个项目对照；其余项目只在确有帮助时引入。先写预测，再看源码与观测。

每日内容包括：

1. 场景与概念，5 分钟：为什么值得学，需要哪些前置知识；先用中文解释名词，再使用英文标识符。
2. 源码精读，20 分钟：选 2–4 个已核验的文件/函数，沿调用链追踪输入、决策、状态变化与输出，解释关键分支。
3. 跨项目对照与设计取舍，10 分钟：比较调度对象、资源归属、数据移动或失败边界，给出一个替代设计及其代价。
4. 实验与观测分析，20 分钟：先预测，执行一个小实验，再解释结果；给命令、观察字段和可推翻预测的现象。复杂实验拆成多天。
5. 自测与复盘，5 分钟：3 个问题，留下一张调用图、约束表或实验结论，并连接下一讲。

深入程度以能解释机制和验证预测衡量。每讲聚焦一个问题，额外阅读标为选读，不要求在一小时内跑完大型构建或跨机器实验。

主题讲解优先于项目新闻；版本更新仅在能解释机制或设计取舍时纳入。没有上游证据时，明确内容基于本地版本，不称为最新实现。
