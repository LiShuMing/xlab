# maze：把生成预算从 64 抬到 1024

## 结论

- 64 token 时 800/800 失败，其中 736 条是截断。抬到 1024 后截断降到 0，但 `pass@1` 仍是 0，
  失败原因仍是 `format` 800/800：截断只是让答卷看不见，不是答不对的唯一原因。
- 关键反证：新 baseline 有 655/800 条输出里能抽出连续动作串（例如 `**U D L R**`），
  逐条按迷宫规则判卷后正确 0 条。base 的失败是双重的：先不守格式，抽出来的内容也错。
- 在 1024 协议下做 answer-only LoRA SFT（200 步，10.09M 参数），full dev 从 0.0000 升到
  0.1600（pass@4 0.2200）；配对比较 delta +0.1600，95% 区间 [+0.1163, +0.2075]，判定 accept。
- 失败结构从"格式"变成"撞墙"：672 条 `wall` 中有 398 条（59.2%）在第 1 或第 2 步就撞墙；
  128 条正确路径全部等于最短长度，没有一条绕路。
- 一句话：SFT 教会了"输出 6 个动作"，没有教会"按网格避墙搜索"。

## 1. 实验设置

| 项目 | 取值 |
| --- | --- |
| 评测配置 | `configs/maze-1024-base.yaml`（`max_new_tokens=1024`、`max_length=1280`） |
| 训练配置 | `configs/maze-1024-sft.yaml`（同预算，rank 16、alpha 16、lr 1e-4、200 步） |
| 数据 | `.local/data/maze-v1`，复用，未重新生成 |
| 新产物 | `.local/maze-1024/{probe,baseline,candidate,sft-runs}` |
| 旧结果 | `.local/baseline-runs/*maze*`（64 token）未改动、未覆盖 |
| 设备与精度 | MPS，float32 |

`max_length` 必须严格大于 `max_new_tokens`，所以预算抬到 1024 时上限同步改为 1280。
为什么 baseline 必须重跑：`max_new_tokens` 会进入评测协议的 `protocol`，旧 64 协议的
`summary.json` 与新协议不相等，`compare` 会直接拒绝。

## 2. baseline：截断消失，成功率不变

| 指标 | 64 token（旧） | 1024 token（新） |
| --- | --- | --- |
| 样本数 | 800 | 800 |
| 生成 token 中位 / 均值 / 最大 | 64 / 62.0 / 64 | 157 / 168.7 / 585 |
| 截断条数 | 736 | 0 |
| `finish_reason` | 736 条 `max_tokens` | 全部 `eos` |
| 失败原因 | `format` 800 | `format` 800 |
| pass@1 / pass@4 | 0.0000 / 0.0000 | 0.0000 / 0.0000 |
| 评测墙钟 | 1278.8s | 3592.4s |

三点观察：

1. 1024 下最长输出 585 token，没有一条撞上限。预算已经足够，继续加大不会改变 baseline。
2. 711/800 条输出含 Markdown 代码块，典型形态是先复述网格、再分步推理、最后给粗体答案。
3. 655/800 条能抽出连续动作串，但这些串几乎都不是可行路径；对它们按 `maze_verdict` 判卷，
   正确 0 条。也就是说，模型并没有"算对了但被格式挡住"的隐藏能力。

这否证了原假设的一半：64 token 确实掩盖了部分输出，但被掩盖的内容本身也是错的。

## 3. SFT：格式被治好，搜索没学会

训练配置只监督回答 token（答案串加 EOS），每个样本的监督信号只有 4 个 token。
轨迹（step 1 到 200）：

| step | loss | grad_norm |
| --- | --- | --- |
| 1 | 8.5572 | 68.43 |
| 25 | 0.5884 | 6.84 |
| 50 | 0.9741 | 11.33 |
| 100 | 1.6063 | 13.23 |
| 150 | 0.4730 | 3.45 |
| 200 | 0.8679 | 9.04 |

loss 在 0.5 到 1.6 之间波动而不再单调下降：4 个 token 的模板很快拟合，剩下的波动来自
不同网格之间的冲突，不是没训够。dev-quick 在 step 100 取到最好的 0.18，step 200 回落到 0.14，
所以候选用的是 `best.pt`。

full dev（200 题 × 4 候选）：

| 指标 | baseline | SFT best |
| --- | --- | --- |
| pass@1 | 0.0000 | 0.1600 |
| pass@4 | 0.0000 | 0.2200 |
| 截断 | 0 | 0 |
| 失败分布 | `format` 800 | `wall` 672 |
| 每样本生成 token | 168.7 | 4.0 |
| 评测墙钟 | 3592.4s | 98.9s |

失败结构（按第一个撞墙的动作序号统计）：

| 第几步撞墙 | 条数 |
| --- | --- |
| 1 | 205 |
| 2 | 193 |
| 3 | 146 |
| 4 | 106 |
| 5 | 20 |
| 6 | 2 |

三类证据说明它学到的是长度模板而不是搜索策略：

- 输出长度恒为 6（797/800 条），而 4×4 迷宫从 S 到 G 的曼哈顿距离恒为 6，任何最短路径
  都恰好 6 步；模型只要输出 6 个字符就"长度正确"。
- 672 条错误里 398 条在前两步就撞墙，说明它没有先读墙再规划的条件行为。
- 128 条正确路径全部等于最短长度，0 条绕路。判卷器不判最短，所以这不是评分规则逼出来的，
  而是训练目标里只有最短解。

按题看：44/200 题至少一个候选正确，其中 19 题 4 个候选全对，12 题 3 个，3 题 2 个，10 题 1 个。
存在一批"模式明显"的题被稳定解出，其余题四个候选一起错。

## 4. 配对比较与成本

| 指标 | 值 |
| --- | --- |
| 题数 | 200 |
| delta（pass@1） | +0.1600 |
| 95% 区间 | [+0.1163, +0.2075] |
| bootstrap | 2000 次，按题聚簇 |
| 判定 | accept |
| limitation | dev 选模证据，不是独立训练种子的重复 |

成本同时被格式治好：输出从 168.7 token 降到 4.0 token，评测墙钟从 3592 秒降到 99 秒
（36 倍），生成 token 从 134992 降到 3200（42 倍）。这解释了 SFT 之后"评测变便宜"不是因为
机器变快，而是因为模型不再写解释。

## 5. 和 countdown、sql 对照

| 任务 | 失败机制 | SFT 后 pass@1 | 解释 |
| --- | --- | --- | --- |
| countdown | 格式 + 部分算术 | 0.2350 | 格式学会，L1 到 L2 有明显能力梯度 |
| sql | 格式 + 模板 | 1.0000 | 规则空间有限，模板补全即可泛化到整个 dev |
| maze | 格式 + 逐题搜索 | 0.1600 | 格式学会，网格条件搜索没有学会 |

同一个 SFT 机制在三个任务上给出三种结果，差别不在训练方法，而在任务需要的归纳偏置：
sql 的答案可以由少量规则组合生成，countdown 可以靠"合法表达式"覆盖一部分，maze 必须
对每道题的网格做条件计算，而 4 个 token 的监督信号承不下这个结构。

## 6. 本机执行记录

- 本机 swap 已占 18.7GB。SFT 第 15 步触发 `paging_slowdown` 停止，且按规则跳过 full dev；
  用 `--resume` 续训一轮后跑满 200 步（44.2s + 142.2s），第二轮才产出 full dev。
- 被中断那一轮的 dev-quick 已经能说明方向：`format` 从 50 降到 1，`wall` 47、`not_at_goal` 1。
- baseline 在 swap 压力下约 4.5 秒/样本；SFT 后约 0.12 秒/样本。
- `--resume` 能成功，是因为换的只是预算段，`max_new_tokens`、数据、模型与源码都没变。

## 7. 局限

- 单 seed、单 adapter、单次训练，没有训练种子重复；结论只到"这一条轨迹上成立"。
- 候选是 `best.pt`（dev-quick 50 题选出的 step 100），full dev 的 0.16 与 dev-quick 的 0.18
  不是同一口径，不能互相替代。
- 1024 协议的结果不能与 64 协议的旧结果直接 `compare`（protocol 不相等），本文只做描述性对照。
- `maze_verdict` 不判最短路径，所以 0.16 里没有"绕路扣分"这一项；如果要研究最优性，需要换指标。

## 8. 下一轮候选

1. 改课程：先把 3×3 迷宫加入训练（路径更短、约束更少），再回到 4×4，看是否形成"先避墙"
   的行为；或者把监督信号从"最终动作串"改成"前缀加最终串"，让 4 token 变长。
2. 用 GRPO：maze 的奖励是 0/1，SFT 已经提供了 128 条正例作起点；组内标准化能把
   "差一步撞墙"和"第一步就撞"区分开，这是 SFT 的固定标签做不到的。
3. 加大 rank：当前 10.09M 参数，若认为瓶颈是容量可试 rank 32；但前两条的预期收益更高，
   优先做课程与奖励。
4. 不做：继续增大 `max_new_tokens`。baseline 最长 585、SFT 后恒为 4，预算已经饱和。

## 9. 复现

```bash
cd labs/reasoning-lab

# 探路：确认 1024 预算下的真实长度与耗时
bash lab.sh run --config configs/maze-1024-base.yaml --split dev --limit 3 \
    --output .local/maze-1024/probe

# baseline（200 题 x 4 候选）
bash lab.sh run --config configs/maze-1024-base.yaml --split dev \
    --output .local/maze-1024/baseline

# SFT；若被 paging_slowdown 中断，用 latest.pt 继续
bash lab.sh run --config configs/maze-1024-sft.yaml
bash lab.sh run --config configs/maze-1024-sft.yaml --resume RUN/checkpoints/latest.pt

# 同一协议下评测 adapter，再做配对比较
SFT=$(ls -d .local/maze-1024/sft-runs/* | sort | tail -1)
bash lab.sh run --config configs/maze-1024-base.yaml --split dev \
    --adapter "$SFT/checkpoints/best.pt" --output .local/maze-1024/candidate

BASE=$(ls -d .local/maze-1024/baseline/*)
CAND=$(ls -d .local/maze-1024/candidate/*)
bash lab.sh compare "$BASE/eval/dev" "$CAND/eval/dev" \
    --output .local/maze-1024/comparison.json
```
